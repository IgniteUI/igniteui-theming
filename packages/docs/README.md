# Ignite UI Theming Docs

Documentation site for the [Ignite UI Theming](https://github.com/IgniteUI/igniteui-theming) library — covering colors, typography, elevations, spacing, sizing, roundness, and component theming for Ignite UI for Angular and Ignite UI for Web Components.

Built with [Astro](https://astro.build/) and served under `/theming-docs/`.

The site is the `packages/docs` workspace of the [igniteui-theming](https://github.com/IgniteUI/igniteui-theming) monorepo and compiles its styles against the sibling `packages/theming` Sass sources. Run the commands below from this folder, or from the repo root with `-w packages/docs` (the root also has `npm run docs` and `npm run docs:build`).

## Installation

From the repo root:

```bash
npm install
```

## Local development

```bash
npm run dev
```

Starts the Astro dev server at `http://localhost:4321/theming-docs/` with hot reload. The Japanese site is at `/theming-docs/ja/`. The search index is only generated by the production build, so the search box is inert in dev.

## Build

```bash
npm run build      # static site into dist/, then the Pagefind search index and the llms*.txt copies
npm run preview    # serve dist/ at http://localhost:4321/theming-docs/
```

Other commands:

| Command              | Description                                                  |
| -------------------- | ------------------------------------------------------------ |
| `npm run check`      | Type-check the Astro, TypeScript and React sources           |
| `npm test`           | Unit tests for the docs model (routes, sidebars, navigation) |
| `npm run lint:style` | Lint CSS/SCSS files                                          |
| `npm run lint`       | `lint:style` + `check` (what the root `npm run lint` runs)   |
| `npm run format`     | Format all source files with Prettier                        |

## How the site is put together

- `docs/`, `versioned_docs/version-24.0.0/` and `i18n/ja/docs/{current,version-24.0.0}/` hold the content (MDX). `src/content.config.ts` loads them as four content collections with a strict frontmatter schema (`title`, `description`, `sidebar_position`, `hide_title`, `pagination_next`).
- `src/lib/docs/` turns the content into doc ids, URLs, the sidebar, previous/next links and breadcrumbs. Sidebar sections and order come from `src/lib/docs/sidebar-defs.ts` (current version) and `src/lib/docs/sidebars/version-24.0.0.json`; category labels and order inside a folder come from that folder's `_category_.json`.
- `src/pages/` holds the routes: the four `[...slug]` doc routes, the landing pages, `404`, `search`, and the `llms.txt`, `llms-full.txt` and `sitemap.xml` endpoints.
- `src/layouts/BaseLayout.astro` and `src/components/layout/*` are the page shell (navbar, footer, colour mode); `src/components/docs/*` the doc page (sidebar, TOC, breadcrumbs, paginator); `src/components/mdx/*` the MDX element overrides (code blocks, admonitions).
- `src/lib/i18n/` provides `translate()`/`<Translate>` for UI strings (messages come from `i18n/ja/code.json`); `src/lib/theme/` the colour-mode hooks; `src/lib/site/useBaseUrl.ts` prefixes paths with the site base.
- `src/styles/` is the design (SCSS on top of igniteui-theming): `base/` holds the generic layout and typography rules, `components/` one partial per component (see `src/styles/README.md`).
- Live samples are React Sandpack components under `src/components/Samples/<Name>/index.tsx`, wrapped by an `index.astro` island; MDX imports the folder.

## Adding content

**A doc page.** Add an `.mdx` file under the right folder in `docs/` with `sidebar_position` (and usually `title` and `description`) in the frontmatter. Folders that are listed as autogenerated in `sidebar-defs.ts` pick it up automatically; top-level pages are listed there explicitly. Add the Japanese counterpart under `i18n/ja/docs/current/` at the same relative path (see the translation workflow below).

**A category.** Create the folder with a `_category_.json` (`label`, `position`, optional `description`, `collapsed`, `customProps.emoji`) and reference it from `sidebar-defs.ts`; add its Japanese label to `i18n/ja/docs/current.json`.

**A live sample.** Copy one of the folders in `src/components/Samples/` (the React component plus its `sandpack/` files and the `index.astro` wrapper) and import it from MDX as `@/components/Samples/<Name>`.

**Admonitions, tabs and code.** `:::note`, `:::info`, `:::danger[Title]` blocks, `<Tabs>`/`<TabItem>` from `@/components/mdx/Tabs.astro`, fenced code with Shiki (`// [!code highlight]` lines, inline `` `code{:scss}` ``) are all supported.

## Versions

`src/lib/docs/config.ts` lists the versions (`current` = v25, `24.0.0`) and their content folders. To snapshot a new version, copy `docs/` to `versioned_docs/version-<V>/`, export the sidebar definition for it to `src/lib/docs/sidebars/version-<V>.json`, add the version to `VERSIONS`, and add a `src/pages/docs/<V>/[...slug]/index.astro` route (and the `ja` counterpart) like the existing 24.0.0 ones.

## Localization (i18n)

The site supports **English** (default) and **Japanese**. Japanese docs live in `i18n/ja/docs/` (`current/` and `version-24.0.0/`), UI strings in `i18n/ja/code.json`, sidebar labels in `i18n/ja/docs/*.json`, and navbar/footer labels in `i18n/ja/theme/`. Missing Japanese UI strings fall back to English.

Japanese translations are handled by an automatic workflow that mirrors each PR: open a PR with English doc changes and set the `status: pending-localization` label, and the workflow generates the translation PR. Manual translation is generally not required.
